# ADR-001: разделение воркспейса на arm_description / arm_moveit_config / arm_control

## Контекст

Исторически воркспейс состоял из пакетов `two_link_description`, `two_link_control`
и `two_link_moveit_config`: два первых были связаны 2-DOF манипулятором, а третий
содержал только YAML и xacro. Имена не описывали роль пакета, а «two_link» перестал
быть правдой после перехода на 6 DOF.

## Решение

Три пакета по ответственности:

| Пакет | Владеет | Сборка |
|---|---|---|
| `arm_description` | модель робота (xacro), мир Gazebo, конфиг RViz, launch визуализации/симуляции | ament_python |
| `arm_moveit_config` | SRDF, kinematics, joint_limits, контроллеры, launch MoveIt 2 | ament_cmake |
| `arm_control` | команды движения и их исполнение через MoveIt 2 | ament_cmake |

Имя робота, сущности Gazebo и макроса ros2_control — `arm`; имя группы планирования —
`arm`; имя контроллера — `arm_controller`.

## Последствия

- По имени пакета видно, что в нём лежит, и в каком пакете искать точку изменения.
- `arm_control` больше не содержит модель: description можно менять, не пересобирая
  логику движения (и наоборот).
- Команды пользователя изменились: `ros2 run two_link_control joint_mover` →
  `ros2 run arm_control move_joints`. Старые имена не поддерживаются.

## Отклонённые альтернативы

- Оставить `two_link_*` и просто добавить 6 DOF — имя вводит в заблуждение и
  продолжает жить в каждом launch-файле.
- Один пакет на всё — любое изменение YAML тянет пересборку всего, и модель
  становится неотделима от логики.
